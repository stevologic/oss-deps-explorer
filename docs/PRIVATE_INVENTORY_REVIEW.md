# Private inventory compatibility proposal

The Wire Hold read-only consumer's first exact-head runner passed its existing
lint/build/fee/contact gates, while inventory failed at `/rulesets`. Both the
existing owner CLI and runner token received GitHub's explicit private-plan feature
message. This is unavailable plan functionality, not evidence that broader scopes
or new credentials are needed. The repository remains private and no purchase,
permission, security or branch-protection setting change is proposed.

Contract 1.1.2 adds only a narrowly identified **partial read-only** report. It labels
protection evidence unknown, preserves all branches, blocks every PR's operations,
disables AI advice and stops both operator merge/deletion paths. Other HTTP/API,
pagination, freshness and mismatched-repository errors continue to fail closed.
The common production and reviewed consumer pins stay at 1.1.1 until this separate
immutable patch has review and the repository's real integration/promotion gates.

Wire Hold has an independent baseline dependency backlog: 9 advisories, 8 high and
1 critical. Its draft consumer must retain the failing full audit gate and PR11/16
holds. A passing partial inventory cannot turn that backlog into validated adoption.
No dependency fix or application/content/provider change is included here.

Validation: common Python safety suite, actual public complete inventory/build CI,
and a separately pinned draft private consumer to verify the real partial receipt.
No local shared browser, native game or Docker resources are required.
